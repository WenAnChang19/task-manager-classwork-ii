## 紀錄一：後端頁面與完成任務操作

遇到的問題：把 Task I 的瀏覽器端陣列及 DOM 更新改成 Express/EJS，並確定完成狀態如何送出。

學生實際提問：「這是task1的repo 先跟我確認所有你覺得需要釐清的技術細節」。該訊息也提供 Express、EJS、port 2234、表單資料處理及伺服器端產生頁面的需求。

AI 實際回覆節錄：「這次要把任務資料與處理邏輯搬到 Express，透過 EJS 產生頁面。」以及「完成狀態採『勾選後按更新』的表單方式，讓每次操作都能清楚對應後端 POST」。

學生實際決定：「保留 採勾選後按更新」。

處理方式：採用後端 tasks 陣列、HTML form、POST /tasks/:id/update。未勾選的 checkbox 不會傳送 completed；後端以 req.body.completed === "on" 明確設定狀態。更新成功後 303 導向 GET，由 EJS 顯示新的清單與統計。

驗證結果：瀏覽器確認只勾選時已完成數仍為 0，按更新才成為 1；另測取消完成及保留篩選。HTTP 測試確認重送相同更新不會把狀態反轉。證據：A1-complete.jpg、browser-tests.json UI04/UI10、node-test-output.txt。

## 紀錄二：SQL 不能只產生看似合理的答案

遇到的問題：指定編輯器有八張資料表，必須使用其實際語法並驗證多表連接與彙總。

學生實際提供的要求節錄：「SQL 指令必須實際執行，不能只提交看起來合理的指令。」以及「請注意：必須正確地從八個資料表選出適當的資料表、連接與篩選。」這些是學生貼上的教師要求，並非另行提出的除錯問題。

AI 實際回覆節錄：「先確認實際環境支援的語法，再決定前五筆及日期條件寫法。」執行後回報：「三題 SQL 已在指定網站執行成功：B1 回傳 7 筆、B2 回傳 5 筆、B3 回傳 8 筆。」

處理方式：Codex 在教師指定網址貼入並執行三題；B2 採用實測可執行的 TOP 5，以 >= 1996-07-01、< 1996-08-01 篩選完整月份。再查出未彙總的 Customer/Order/Product/Price/Quantity 明細，用 JavaScript 另行計算總額、前五名及 Tofu 明細。沒有虛構學生親自改寫或測試的經過。

驗證結果：實際 518 筆連接明細重新計算後，三題排序及數值均一致。B1 以整數分計算避免浮點誤差。證據：sql-results.json、sql-detail.json、sql-verification.json 及 B1/B2/B3 網站截圖。
